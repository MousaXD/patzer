## New verified defects and fixes

1. **P1 malformed hosted UCI moves** (`server/src/chess/engine.ts`): `chess.js` accepts a move like `e2e4q` and silently ignores the extraneous `promotion` parameter; prior hosted response parsing therefore accepted a syntactically plausible but illegal UCI move. Verify that the actual applied move's promotion matches the UCI suffix for both the best move and every continuation ply. Invalid continuations are truncated; an invalid best move rejects the remote result.
2. **P1 impossible hosted score claims** (`server/src/chess/engine.ts`): a hosted response with `mate: 0` and a legal best move previously became a mate-zero claim on a nonterminal board, and a fractional mate distance could also be accepted. Only finite, safe, nonzero integer mate distances are accepted when a best move exists. A missing/invalid mate without a valid centipawn score fails closed. Invalid declared search depths (negative, fractional, nonfinite or unsafe integer) now reject rather than becoming a misleading reported budget. Optional omitted depth remains `0` for existing provider compatibility.
3. **P1 contradictory scored Stockfish roots** (`server/src/chess/stockfish.ts`): the previous agent fix suppressed MultiPV candidate-gap evidence when `bestmove` disagreed with the scored rank-one PV, but it still returned that rank-one numeric score. A synthetic UCI line `+260cp pv e2e4` followed by `bestmove d2d4` was accepted as a +260cp root, even though the final choice and scored PV disagree. Both `evaluate()` and `evaluateMulti()` now throw `engine_inconsistent_pv` for a scored **nonterminal** position with a contradictory, illegal or missing PV first move. Terminal positions with no legal moves retain legitimate `mate 0`/`cp 0` semantics. The analyzer therefore cannot persist potentially fabricated accuracy from the inconsistent root.
4. **P1 unvalidated direct bot/hint best move** (`server/src/chess/stockfish.ts`): the bare `bestMove()` method returned a fake UCI `bestmove e2e5` from the standard starting FEN, without a legality check. It now legally replays that single move and rejects it as `engine_illegal_bestmove`; normal legal bot/hint best moves and `(none)` for terminal positions remain supported.

New negative controls failed on the original implementation and passed after their respective fixes. No coefficient, score version, formula, cached analysis, database schema, or PR #17 file was changed. No private games, production SQLite, active service, secrets, deployment configuration, or other branch was written.
